# 인수인계 문서 — 헬스셀러 (health-seller.com)

이 문서 하나로 서비스를 넘겨받아 운영·개발할 수 있게 쓴 것입니다. 계정 권한 이관 절차는
[`HANDOVER-accounts.md`](HANDOVER-accounts.md), 기능 명세는 [`SPEC.md`](SPEC.md)를 봅니다.

---

## 1. 서비스가 하는 일

건강기능식품을 **위탁판매**하는 셀러를 위한 업무 도구입니다. 셀러의 작업 순서를 그대로
메뉴 구조로 만들었습니다.

```
찾기            만들기              운영            정산
증상 지도   →   썸네일          →   CS 답변    →   마진 계산
상품 소싱       상품명·태그
홈쇼핑 편성     후킹페이지
```

| 메뉴 | 경로 | 하는 일 |
|---|---|---|
| 홈 | `/` | "오늘 할 작업" 런처 + 홈쇼핑 트렌드 + 최근 작업 |
| 증상 지도 | `/map` | 인체 지도 → 부위 → 증상 → 추천 원료 |
| 상품 소싱 | `/sourcing` | 도매 3사 상품 6,003건 — 가로 행 목록, 정렬 4종·시장 신호·타몰 시세 |
| 홈쇼핑 편성 | `/broadcast` | 예정 방송 · 준비 기간 긴 순 (매일 05:00 수집) |
| 썸네일 | `/studio` | AI 배경·인물 + 상품 누끼 합성 → PNG |
| 상품명·태그 | `/titles` | 노출도 등급 상품명 + 태그 20개 |
| 후킹페이지 | `/hook` | 상세페이지 상단 2장 — AI 씬 + 문구 + 스타일·위치 편집 |
| CS 답변 | `/cs` | 고객 문의 → 운영 정책 기반 답변 초안 |
| 마진 계산 | `/margin` | 수수료·세금 뺀 실마진, 손익분기 ROAS |
| 내 계정 | `/my` | 작업 이력 · **AI 생성 이력** · **운영 프로필** · 마진 이력 |
| 관리자 | `/admin` | 수강생 코드 발급 · 회원 관리 |

**수강생 전용입니다.** 로그인만으로는 대시보드가 열리지 않고, `profiles` 행이 있어야
합니다. 그 행은 수강생 코드를 낸 사람에게만 생깁니다.

## 2. 기술 구성

| 영역 | 사용 기술 |
|---|---|
| 앱 | Next.js 15 App Router (Server Actions + Route Handlers) |
| 배포 | **OpenNext → Cloudflare Workers** (Node가 아니라 workerd에서 돕니다) |
| DB·인증 | Supabase (`medidash` 스키마, RLS) |
| AI | OpenAI — **`gpt-image-2`**(후킹 씬), `gpt-image-1`(썸네일 배경·인물), `gpt-4o-mini`(텍스트) |
| 이미지 처리 | Cloudflare Images `segment=foreground` (썸네일 누끼) |
| 인증 | 이메일 + 수강생 코드 / 카카오·구글 소셜(**제공자 미설정**) |
| 배치 | GitHub Actions (홈쇼핑 지표 일 1회) |

### 로컬 실행

```bash
npm install
cp .env.example .env.local     # 키 채우기
npm run dev                    # http://localhost:3000
```

**키 없이도 실행됩니다.** Supabase 환경변수가 비면 mock 모드로 뜨고, 로그인 없이 시드
데이터로 전 화면을 볼 수 있습니다. 단 **프로덕션(NODE_ENV=production)에서는 mock으로
떨어지지 않고 즉시 실패합니다** — 설정 실수 하나가 "인증 없는 공개 사이트"가 되는 것을
막기 위해서입니다 (`src/lib/supabase/env.ts`).

> ⚠️ **dev 서버가 떠 있는 동안 `npm run build`를 돌리지 마세요.** 프로덕션 빌드가 dev의
> `.next`를 덮어 캔버스가 안 그려지는 등 엉뚱한 증상이 납니다. 꼬였으면 `.next`를 지우고
> dev를 재시작하면 됩니다.

```bash
npm run build      # 타입체크 + 빌드
npm test           # 83건
npm run lint
npm run cf:deploy  # Cloudflare 배포
```

> 🔴 **브랜치를 push하면 프로덕션이 덮입니다.** Cloudflare Workers Builds가 main만이
> 아니라 **모든 브랜치 push마다 프로덕션에 배포**합니다. 2026-08-01에 PR #35·#36이
> 열려 있는 상태에서 프로덕션이 #36 코드로 돌고 있는 것을 확인했습니다(본문 상한
> `max-w-7xl`이 #36에만 있는 값이라 확정). PR 리뷰가 실질적인 관문이 아닙니다.
> 수강생 오픈 전에 Workers Builds 설정에서 프로덕션 브랜치를 `main`으로 제한해야 합니다.

## 4. 넘겨받는 사람이 먼저 알아야 할 것

여기 적힌 것들은 **직접 부딪혀서 알아낸 것**이라 코드만 봐서는 안 보입니다.

### 4-1. 로컬에서 되고 배포에서 깨지는 것들

`workerd`는 Node가 아닙니다. 아래는 전부 로컬 통과 후 프로덕션에서 발견됐습니다.

- **2MB 서버 액션** — 인물 컷아웃(투명 PNG 1.5MB)을 서버 액션으로 돌려주면 조용히 실패합니다. 그래서 `/api/ai/image`가 라우트 핸들러이고 **원본 바이트를 그대로** 내보냅니다.
- **`next.config.ts`의 `headers()`가 무시됩니다** — 정적 자산 캐시는 `public/_headers`로 설정해야 합니다.
- **`/cdn-cgi/image/` 를 서버에서 부르면 안 됩니다** — Worker가 자기 도메인의 그 경로를 fetch하면 엣지를 안 타고 Worker로 되돌아와 원본이 나옵니다. **브라우저가 직접** 불러야 합니다.
- **Durable Object는 `new_sqlite_classes`** — 무료 플랜은 KV 기반 DO를 지원하지 않습니다.
- **DO 프록시는 JSON 본문만 나릅니다** — `JSON.stringify(FormData)`는 `{}`가 되어 본문이
  통째로 사라집니다. multipart는 `Request`로 인코딩한 바이트를 base64로 넘겨야 합니다
  (씬 생성이 이것 때문에 프로덕션에서 400으로 죽었습니다).

### 4-2. OpenAI가 한국에서 403을 냅니다

한국 트래픽이 Cloudflare 홍콩(HKG) PoP로 나가는데 OpenAI가 홍콩을 차단합니다.
Smart Placement로는 안 풀렸습니다. **`locationHint: "wnam"`으로 북미에 고정한 Durable
Object를 경유**해 해결했습니다 (`worker-entry.ts`, `src/lib/ai/fetch.ts`).
OpenAI 호출만 이 경로를 타고 나머지는 사용자 근처 엣지에서 처리됩니다.

### 4-3. 상품 이미지 생성은 `gpt-image-2`만 씁니다

`gpt-image-1`의 편집은 편집이 아니라 재생성이라 **패키지의 한글 표시사항이 깨집니다.**
실측에서 **"종근당" → "증근당"** 이 나왔습니다.

**`gpt-image-2`로 다시 재보니 보존됩니다.** 같은 상품(종근당 프리미엄 MSM)으로 측정한 결과
브랜드·기능성 문구·함량·GMP·건강기능식품 마크까지 **정면 표시사항이 한 글자도 안 틀렸습니다.**
그래서 후킹페이지는 상품 사진을 참고 이미지로 넣어 씬을 통째로 만듭니다.

- 모델은 **`AI_SCENE_MODEL`로 따로 잡습니다**(기본 `gpt-image-2`). `AI_IMAGE_MODEL`이
  `gpt-image-1`로 남아 있으면 깨진 결과가 그대로 나갑니다.
- **원본에 안 보이는 면은 모델이 지어냅니다** — 병 측면 세로 글자가 판독 불가한 뭉치로
  나왔습니다. 프롬프트로 "원본에 보이는 각도 그대로"를 명시해 줄이되 완전히는 못 막으므로
  화면 고지로 검수를 안내합니다.
- 인물은 AI가 만든 가상 인물이라 생성해도 됩니다.

### 4-4. 도매몰 상세 텍스트는 쓸 수 없습니다

`wholesale_products.detail.text`는 사실상 비어 있습니다. 3사 실측:

| 몰 | 내용 |
|---|---|
| gonyb2b | 0자 |
| ggsan | 258자 — 전부 `상품상세정보 / 배송안내 / 교환 및 반품안내` 탭 레이블 |
| upickb2b | 0자 |

**원료 매칭에 이 텍스트를 넣으면 안 됩니다.** 판매정책 안내문이라
"블루베리(삼성복지몰)" 같은 오탐이 납니다. 대신 **상품명 파서**(`src/lib/products/parse-name.ts`)로
브랜드·제형·함량·수량을 뽑습니다 — 6,003건 기준 규격 76.2% · 브랜드 91.1%.

### 4-5. 홈쇼핑 편성표는 열흘치만 공개됩니다

예정 편성 325건 실측: 최대 D-9.8, 중앙값 D-0.8, **14일 이상 0건**. 홈쇼핑모아가 상위
10건만 주는 상한 때문이 아닙니다(10건이 꽉 찬 원료보다 전량 수집된 원료가 오히려
더 멀었습니다). **매일 크롤이 이 기능의 전제**입니다 — 월 1회면 대부분을 놓칩니다.

### 4-6. 증상 지도가 비어 보이는 건 버그가 아닙니다

"특징·기전원리·셀링포인트·원료가 전부 안 나온다"는 신고가 있었는데 **원인이 둘로
갈립니다.** 실측(2026-08-01):

| | 상태 |
|---|---|
| `subcategory_contents` | **0건** — 어느 부위를 열어도 4개 탭 본문이 빕니다 |
| `symptom_ingredients` | 51건이 **21/32 부위에만** — 나머지 11개는 원료 칩도 빕니다 |

원료 87종 중 **67종이 어느 증상에도 안 붙어 있고, 그중 63종은 실제 상품이 있습니다.**
프로폴리스 130건·비타민D 274건·콜라겐 184건이 그렇게 놀고 있습니다. 상품이 없어서가
아니라 `증상 → 원료` 한 줄이 없어서 화면이 빈 것입니다.

`ingredients.note`는 87종 다 차 있지만 **전부 `[샘플]` 표시**라 실데이터가 아닙니다.

> 채우는 건 기술적으로 몇 시간이지만 **SPEC §2가 콘텐츠 창작을 막습니다.**
> 다만 발주처가 "셀러용 소싱 가이드이지 소비자 판매 페이지가 아니다"라는 근거로
> 식약처 인정 기능성 기반 매핑 + 고지 문구 방식을 요청했습니다(2026-08-01).
> 진행한다면 **식약처 고시 문구만 근거로 쓰고 근거를 데이터에 함께 저장**해야 합니다.

### 4-7. 광고법 가드는 코드에 있습니다

의약품 오인 표현(치료·완치·개선·효과…)은 `src/lib/titles/compliance.ts`의
`sanitize()`가 치환합니다. **AI가 만든 문구는 반드시 이걸 통과시켜야 합니다.**
프롬프트로 금지해도 샙니다. 상품명·태그·후킹 문구 모두 적용돼 있습니다.

### 4-8. CS 답변은 운영 프로필 없이 부르면 안 됩니다

배송 정책을 모른 채 "배송 언제 오나요"에 답하면 **지어낸 날짜가 나가고 그대로 클레임**이
됩니다. 그래서 `profiles.ops_profile`에 상호명·배송 정책이 없으면 채팅 입력을 잠급니다.

화면에서만 막으면 안 됩니다 — **서버 액션은 화면을 거치지 않고 직접 호출될 수 있어**
`askCsAction`에서도 다시 확인합니다. 같은 이유로 `/api/ai/image`는 프로필 유무를 직접
검사합니다(`api/`는 미들웨어 matcher에서 제외돼 있습니다).

### 4-9. 비용 방어

- AI 호출 한도는 **이미지와 텍스트가 따로**입니다 — 1회 비용이 100배 차이나기 때문입니다
  (`gpt-image-1` 20~200원 / `gpt-4o-mini` 0.3원). 기본 이미지 5회·텍스트 50회
  (`AI_IMAGE_DAILY_LIMIT`·`AI_TEXT_DAILY_LIMIT`, 관리자 제외).
- **유료 호출 직전에 차감**하므로 생성이 실패해도 1회가 빠집니다. 그래서 `ai_logs`에
  성공·실패·한도초과를 모두 기록하고 마이페이지에 보여줍니다.
- 결과물 **원본은 저장하지 않습니다.** 후킹페이지 2장 PNG가 세트당 3MB라 수강생 50명이
  하루 2세트만 만들어도 월 9GB가 됩니다. 512px WebP 미리보기(세트당 80KB)만 남깁니다.

### 4-10. 화면은 50~60대 기준으로 잡혀 있습니다

발주처가 밝힌 주 사용자가 **50~60대**입니다. 이 전제로 다음을 고정해 뒀으니
새 화면을 만들 때도 지키세요.

| 항목 | 기준 | 어디에 |
|---|---|---|
| 글자 | 최소 14px · 본문 16px | `globals.css`의 `--text-*` 토큰을 한 단씩 올려 둠 |
| 대비 | WCAG AA 4.5:1 | `slate-400`(2.56:1)·`slate-300`은 쓰지 마세요 |
| 표적 | 44×44px 이상 | 버튼·링크·입력 전부 |
| 한글 줄바꿈 | `word-break: keep-all` | body에 전역 적용 |

**`text-xs`는 이제 14px입니다.** 토큰을 올렸으므로 클래스 이름과 실제 크기가 다릅니다 —
`text-[10px]` 같은 임의 값은 토큰이 안 닿으니 쓰지 마세요.

밀도도 같이 조정했습니다. 글자를 키우면 한 화면에 들어가는 양이 줄어서, 소싱 목록은
세로 카드(637px·1.4장)에서 **가로 행(299px·3.0장)** 으로 바꿨고 카드 동작을 아홉 개에서
두 개로 줄이고 나머지는 `<details>`로 접었습니다. **선택지가 많은 것 자체가 이 연령대에는
부담입니다.**

캔버스에 직접 그리는 색은 Tailwind 토큰이 안 닿습니다 — 팔레트를 바꾸면
`ThumbnailStudio`의 `BADGE_INK`, `BodyMap3D`의 포커스 링, `hook/render.ts`의 기본
강조색, `thumbnail/backgrounds.ts`의 `DEFAULT_PALETTE`를 **같이** 고쳐야 합니다.

## 5. 벤치마킹 기준

경쟁 서비스 **빽형 건기식 AI 마스터**(`bbaek-hyung-web.vercel.app`) 8개 메뉴를 분석해
화면 문법을 맞췄습니다.

**우리만 있는 것**: 썸네일 스튜디오 · **후킹페이지 스튜디오** · 증상 지도 기반 소싱 동선 ·
광고법 자동 치환 · 홈쇼핑 리드타임 정렬
