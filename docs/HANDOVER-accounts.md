# 계정 이관·권한 요청 가이드 (고객사 ↔ 마그네이트코리아)

서비스 운영에 쓰이는 외부 계정을 **고객사 명의로 두고, 개발사(마그네이트코리아)를 관리자로 초대**하는 구조로 정리하기 위한 문서입니다.

---

## 1. 왜 고객사 명의여야 하는가

| | 개발사 명의로 두면 | 고객사 명의로 두면 |
|---|---|---|
| 비용 청구 | 개발사 카드로 나가고 정산이 별도로 필요 | 고객사에 직접 청구 — 정산 불필요 |
| 계약 종료 시 | 계정·데이터 이관 작업이 다시 발생 | 개발사 권한만 회수하면 끝 |
| 서비스 중단 위험 | 개발사 카드 만료·한도 초과 시 서비스가 멈춤 | 고객사가 직접 통제 |
| 데이터 소유권 | 소유 관계가 모호해짐 | 명확히 고객사 |

**핵심은 "소유는 고객사, 운영 권한은 개발사"** 입니다.

## 4. 작업 순서 ⚠️ 순서가 중요합니다

### 4-1. Supabase를 **가장 먼저** 만듭니다

소셜 로그인(구글·카카오·네이버)은 전부 이 주소를 콜백으로 씁니다.

```
https://<프로젝트ref>.supabase.co/auth/v1/callback
```

`<프로젝트ref>`는 **프로젝트마다 다릅니다.** 구글·카카오·네이버 앱을 먼저 만들어 놓고 나중에 Supabase를 새로 만들면, **세 콘솔의 콜백 주소를 전부 다시 등록해야 합니다.**

- 기존 프로젝트를 그대로 쓰는 방법도 있습니다 → **4-2 참고** (데이터 이관이 필요 없어 더 유리합니다)
- **무료 플랜은 1주간 미사용 시 프로젝트가 자동 정지**됩니다. 수강생에게 열기 전 **Pro($25/월)** 로 올려야 합니다.

### 4-2. 프로젝트를 새로 만들고 데이터만 옮깁니다

Supabase는 조직 간 프로젝트 이관을 지원하지만, **이 프로젝트에는 헬스셀러가 아닌 다른 서비스의 데이터가 함께 들어 있어 통째로 넘길 수 없습니다.**

현재 이 Supabase 프로젝트에 존재하는 저장소 버킷:

| 버킷 | 소속 |
|---|---|
| `previews` | 헬스셀러 |
| `case-reports` · `invoices` · `contracts` · `estimates` · `contract-signatures` | **다른 서비스** |

프로젝트를 통째로 이관하면 위 다른 서비스 데이터까지 고객사 소유가 됩니다. 그래서 **고객사 조직에 헬스셀러 전용 프로젝트를 새로 만들고, 헬스셀러 데이터만 옮기는 방식**으로 진행합니다.

옮길 대상:

- `medidash` 스키마 전체 (회원·상품 6,003건·키워드·방송지표·작업 이력)
- `auth.users` (수강생 계정)
- `previews` 버킷

> **이 방식은 Supabase 주소가 바뀝니다.** 4-1에서 설명한 콜백 주소가 달라지므로, **소셜 로그인은 반드시 새 프로젝트를 만든 뒤에 설정해야 합니다.** 순서를 지키면 재작업이 없습니다.

> 무료 조직은 프로젝트 2개 제한이 있어, 받는 쪽에서 먼저 Pro로 올려두는 편이 안전합니다.

### 4-3. 나머지는 순서 무관

Supabase 콜백 주소가 확정된 뒤에는 구글·카카오·네이버·Cloudflare·OpenAI를 병렬로 진행해도 됩니다.

## 5. 서비스별 초대 경로

### Supabase
`Organization Settings` → `Team` → `Invite member` → 역할 **Owner** 또는 **Administrator**

### Cloudflare
`Manage Account` → `Members` → `Invite` → 역할 **Super Administrator - All Privileges**

> Workers 배포·DNS·Images를 모두 다뤄야 해서 부분 권한으로는 부족합니다. 세팅 완료 후 축소 가능합니다.

### OpenAI
`Settings` → `Organization` → `Members` → `Invite` → **Owner** 또는 API 키 발급이 허용된 **Member**

> 예산 사고를 막으려면 `Settings` → `Limits` 에서 **월 사용 한도(Hard limit)** 를 함께 걸어두시길 권합니다.

### Google Cloud
1. 전용 프로젝트 생성 (예: `health-seller`)
2. `IAM 및 관리자` → `IAM` → `액세스 권한 부여` → 역할 **소유자(Owner)**

> OAuth 동의 화면 게시·검증은 소유자 권한이 필요합니다.

### Kakao Developers
1. [developers.kakao.com](https://developers.kakao.com) → `내 애플리케이션` → **앱 생성**
   - 앱 이름: `헬스셀러`
   - **회사명: 고객사 사업자등록증상 상호와 동일하게** ← 심사에 쓰입니다
2. `앱 설정` → `팀 관리` → 팀원 초대 → 권한 **관리자**

> **비즈 앱 전환**: 카카오 로그인에서 **이메일을 필수 동의 항목으로 받으려면 비즈 앱 전환**이 필요하고, 사업자등록증이 요구됩니다. 우리 서비스는 이메일이 있어야 계정을 만들 수 있어 **필수 절차**입니다.

### Naver Developers
1. [developers.naver.com](https://developers.naver.com/apps/#/register) → 애플리케이션 등록
   - 사용 API: **네이버 로그인**
   - 제공 정보: **회원이름·이메일 (필수)**
2. `내 애플리케이션` → `멤버 관리` → 관리자 추가

### 도메인
`health-seller.com` 을 고객사 명의로 옮기거나, 네임서버를 Cloudflare로 위임합니다.

> **Cloudflare Images 배경제거 기능은 도메인이 Cloudflare에 붙어 있어야 동작합니다.** 도메인이 빠지면 상품 이미지 누끼 기능이 멈춥니다.

## 7. 이관 후 개발사가 할 일

계정을 받은 뒤 개발사 쪽 작업입니다. 고객사 조치는 필요 없습니다.

1. 고객사 조직에 헬스셀러 전용 Supabase 프로젝트 생성 + 스키마 마이그레이션 실행
2. 데이터 이관 — `medidash` 스키마, `auth.users`, `previews` 버킷
3. Cloudflare 새 계정에 Worker 재배포 (**Workers는 계정 간 이전이 불가**해 재배포가 필요합니다)
4. 커스텀 도메인 `health-seller.com` 연결
5. Supabase 키·OpenAI 키를 배포 환경변수로 교체
6. GitHub Actions 시크릿 교체 (홈쇼핑 지표 일 1회 자동 수집용)
7. 구글·카카오·네이버 콜백 주소 등록 및 로그인 검증
8. 구 계정 권한 회수

> 2번 데이터 이관 중에는 서비스가 잠시 멈춥니다. 수강생 이용이 적은 시간대에 진행합니다.
